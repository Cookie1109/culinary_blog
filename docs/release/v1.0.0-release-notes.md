# Culinary Blog v1.0.0 — release notes

> Trạng thái: **Release Candidate / No-Go production** ngày 05/10/2026. Không đổi thành Released cho đến khi mọi ô bắt buộc trong go/no-go được ký và production smoke pass.

## Phạm vi

v1.0.0 cung cấp đăng ký/đăng nhập và quản lý phiên an toàn; phân quyền Guest/Author/Admin; quản lý category; toàn bộ vòng đời recipe với ingredient, step và image; publish/search/filter/sort; public web/SEO; dashboard; audit và observability. Google OAuth không nằm trong RC theo ngoại lệ Should-have đã công bố.

## Định danh artifact

Nguồn chuẩn là artifact `release-bundle-<full-git-sha>` của workflow `release-images.yml`. Khi chọn RC, Release Manager phải ghi:

| Trường | Giá trị đã duyệt |
|---|---|
| Git commit SHA | Chờ điền |
| Release bundle run/URL | Chờ điền |
| Release bundle artifact digest | Chờ điền |
| API image + digest | Chờ điền |
| Web image + digest | Chờ điền |

Staging và production phải dùng đúng hai `image@sha256` trên. Không rebuild, retag hoặc thay manifest sau UAT; mọi thay đổi tạo RC mới và chạy lại gate bị ảnh hưởng.

## Bằng chứng hiện có

- Functional regression: 58 unit, 3 architecture, 50 integration và 69 frontend test đã pass tại local hardening/release-engineering run.
- Performance: API p95/p99, cache hit rate, bundle và Lighthouse budgets đạt trên profile local đã công bố.
- Security: dependency/container/secret/license scans và ZAP local không có Critical/High; staging HTTPS ZAP vẫn bắt buộc.
- Reliability: restore drill local đạt RTO 10,45 giây/RPO 11 giây; dependency failure drills, restart policy và alert path pass local.

Số liệu chi tiết nằm trong [Phase 8](../specs/phase-8/README.md), [performance](../reports/phase-8-performance-report.md), [security](../reports/phase-8-security-report.md) và [reliability](../reports/phase-8-reliability-report.md).

## Điều kiện phát hành còn lại

- Deploy immutable RC lên staging bằng [production Compose](../../infra/production/compose.production.yaml) và lưu `release-gate.json`/`staging-deployment.json`.
- Chạy ZAP staging HTTPS, performance, restore/failure drill, alert delivery và CJ-01…CJ-05 browser UAT trên đúng artifact.
- Không còn Critical/High; Medium phải có owner, due date và risk acceptance nếu chưa sửa.
- Product Owner ký [UAT](uat-signoff.md); Technical Lead/Release Manager ký [go/no-go](go-no-go-and-rollback.md).
- Production deploy, smoke, dashboard/alert verification và theo dõi tăng cường 24–48 giờ.
